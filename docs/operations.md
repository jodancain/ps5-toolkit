# 操作与故障记录

## 服务

| 服务 | 端口 | 用途 |
| --- | --- | --- |
| Payload Manager | 8084 | 查看进程、payload 和自动加载配置 |
| shsrv | 2323 | TCP shell，不是 SSH |
| ftpsrv | 2121 | 文件传输 |
| ShadowMountPlus | 10101 | 加载器 Web 界面 |
| PS5 Tailscale | 8090 | Tailscale 管理界面 |

shsrv 和 FTP 本身不加密。此环境通过局域网使用，远程访问依靠 Tailscale。不要把这些端口直接暴露到公网。主机关机、休眠或未恢复运行环境时，不保证可远程连接。

## 已观察到的启动故障

1. 游戏目录安装成功，但启动返回 `0x80020008`。
2. 检查发现 eboot 和多个模块为裸 ELF。
3. 保留原文件后，使用上游 fake-sign 工具转换成 SELF，传输并校验。
4. ShadowMount 日志随后出现 `GAME started`，进程列表存在 `eboot.bin`。
5. 仅有进程证据不等于完整通关或长期稳定性验证；画面仍需现场确认。

不能把所有启动错误都归因于文件格式；先检查插件、版本、日志和文件完整性。

## 崩溃后的检查

后续检查时，远程 shell 和 Tailscale 正常，但 kstuff 与 ShadowMount 均未运行。
自动加载列表只有 shsrv 和 Tailscale，因此重启后仍可连接，却可能无法运行目录游戏。

处理顺序：

1. 查看 Payload Manager 进程列表，避免重复加载或混用不同 HEN。
2. 在匹配的固件环境中先恢复 kstuff，再恢复 ShadowMount。
3. 需要传输或校验文件时启动 ftpsrv。
4. 检查 `/data/shadowmount/debug.log` 与应用文件，再尝试启动。

本次恢复后已确认上述三个插件进程存在；后续游戏验证被新的上传任务打断，不能据此认定恢复后的游戏已正常显示。
没有足够日志证据判断最初崩溃由哪个操作或工具造成。

## 自动加载

本次既有配置只自动加载 shsrv 和 Tailscale，延迟五秒。此记录不包含真实配置文件。
修改自动加载前应先验证插件兼容性与加载顺序，并保留原配置；本仓库不自动改变它。
